Data-quality flag 1 — session timing is unusable: session_position_of_first_search is UNKNOWN_TIMING for 100% of rows, confirmed on the full table. The START/MIDDLE/END logic never fires — almost certainly a unix_timestamp() format mismatch, since it defaults to expecting yyyy-MM-dd HH:mm:ss and the session timing columns in va_user_session_activity are likely a different format (ISO-8601 with T/timezone/millis). Fix the format string before relying on this field anywhere.
Data-quality flag 2 — trailing newline in scat names: some Kids sub-category values carry a literal trailing newline (e.g. "Kids - Girls Western Wear\n"). This is present consistently on both the search-side and pre-browse-side scat values, so scat-grain matching is unaffected, but it will silently break joins/dedupes against any table where the same category isn't newline-suffixed.
Data-quality flag 3 — L2 unavailable: the nudge-vs-organic split (previously L2) cannot be reproduced from the current full-population export, which does not include a first_search_source column (see the flag above section L0).

Methodology & caveats

Single source, single population. This version of the report is rebuilt end-to-end from one file: the full 352,400-row session export (the same file used for sections M–O in the prior version). Every section — L0 through O — now uses the identical 157,210-session qualifying population (44.6% of 352,400): sessions with both a pre-search browsing signal (any screen — home feed, search results, category pages, widgets, not home-feed-only) and a resolved search category. Nothing in this document is sample-based any longer; L4 and L5 were previously computed on a 10,000-row sample and are now exact, computed on the full qualifying population.

What "Same-dominant / Same-in-set (non-dominant) / Combined / Different" means. Same-dominant = the search's resolved category (at the stated grain) matches the single most-viewed category in the session's pre-search views. Same-in-set (non-dominant) = it matches a category viewed, just not the single most-viewed one — computed as dominant checked first, then set-membership checked on whatever's left, so it deliberately excludes dominant matches rather than including them. Combined = same-dominant + same-in-set (non-dominant), i.e. the search matched anything at all in the pre-search set, dominant or not. Different = it matches none of the pre-viewed categories. Same-dominant, same-in-set (non-dominant), and Different always sum to 100% of the qualifying population at each grain; Combined is the derived sum of the first two, so Different = 100% − Combined.

Category hierarchy rollup. sscat (finest) → scat → category (coarsest). The base export only carries sscat-level match natively (pre_sscat_set, pre_dominant_sscat_id); scat/category-level matching was computed locally by mapping every sscat_id in pre_sscat_set to its scat/category via a static dimension table, then checking whether the search's resolved scat/category falls in that mapped set (same-in-set) or equals the dominant sscat's mapped scat/category (same-dominant).

L2 (nudge vs. organic) is not reproducible from this export — see Data-quality flag 3.

Query intent classification is keyword-based regex matching on the lower-cased search string (color names, size/unit tokens, gender/age words, material fabrics, occasion words, price/budget phrases, pack/quantity phrases) — a coverage heuristic, not an NLP intent model; categories are non-exclusive.

Known limitations carried over from the source query: session_position_of_first_search is non-functional (see flag 1); pre-search browsing/clicks use an any-origin definition (not home-feed-only), so absolute match rates here are structurally higher than an earlier, narrower iteration of this analysis that restricted pre-signal to the home feed only — that iteration has been fully superseded by this single-source rebuild.
