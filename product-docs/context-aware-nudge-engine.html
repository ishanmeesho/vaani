Builds on KRD — Vaani Zero-Click Nudge MVP (v1)

Section I: Executive Summary

1. Problem Statement

In v1 we built capability to fire a client-side zero-click nudge when a user views enough products without clicking.The nudge content was deliberately blunt: one static Hindi line, the same copy for everyone, no memory of who the user is or what they did in prior sessions. Every eligible user hears the same thing regardless of whether they were deep in one category yesterday, are shopping in a category for the first time, or are browsing wide with no clear intent.

v2 turns that single blunt trigger into a small catalogue of context-aware nudges. The nudge that fires — and the exact words spoken — should depend on:

(a) whether the user is an exploit user (repeatedly returning to one sub-category, S) or an explore user (browsing wide)

(b) what they did in the current session (clicks, searches), and

c)what they did in prior sessions (a product clicked but not re-found, an abandoned cart/payment).

On top of that, the nudging infra should be able to bank optional user-profile fields (name, city, sizes, preferred category, language, device) and resolve them into copy so the nudge feels personal — without needing a client release each time.

This KRD covers the personalization and prior-session-memory layer. It reuses the v1 client counter machinery and the shipped rule/config format, adds sscat-tagged instrumentation, a backend session-start context payload, a nudge catalogue with a priority resolver, back-off / fatigue controls, and a bankable profile-placeholder mechanism. It does not cover full generative nudge-time content or a general cross-surface orchestration engine beyond what the catalogue and resolver need.

2. Product Thinking — what v2 must prove

The v1 told us zero-click nudging is buildable and fireable. v2 must show it is worth personalizing. Four claims we want the experiment to support or reject:

  1. Context-matched copy beats a single static line — a nudge that names the sub-category / prior product the user was actually on earns more Vaani initiations than the v1 static line.

  2. Prior-session memory is high-value — re-surfacing a previously clicked-but-not-found product, or an abandoned cart, converts above the exploit base nudge.

  3. Explore users are a real, under-served segment — a predicted-basket / open-need nudge for wide browsers produces initiations we are leaving on the table today.

  4. Personalization does not raise fatigue — with back-off and caps in place, added nudge variety does not increase ignored-rate or app-exit versus v1.

2. Scope

2.1 In Scope

  1. Backend session-start context payload consumed by the client (exploit/explore label, dominant sscat S, new-to-category flag, predicted basket Z + confidence, prior-session hooks, optional profile placeholders).

  2. sscat-tagged product impression & click instrumentation (extends v1 raw counters with per-sscat maps).

  3. Derived per-sscat counters on client: S-share of views/clicks, distinct-sscat count, Y (categories viewed).

  4. Nudge catalogue: E1, E1-NTC, E1-RV, E2, E3, E4a, E4b (exploit) and X1, X2 (explore), placeholder-driven copy.

  5. Priority resolver firing at most one nudge per session across the catalogue.

  6. Back-off / fatigue state: session cap, lifetime cap, ignored-count and ignored-% over a rolling x-day window.

  7. Bankable user-profile placeholders resolved into copy, gated by privacy use-mode.

  8. Remote-config schema v2 (context block + priority + content_key + placeholder tokens).

  9. User-level sticky A/B with an eligible-Holdout arm and leaf-level attribution.

2.2 Out of Scope

  1. Fully generative, backend-rendered nudge-time content (v2 uses templated copy with placeholders; generation is a later phase).

  2. A general cross-surface orchestration engine beyond the catalogue + resolver.

  3. ML drop-off prediction as a trigger (the predicted basket Z is an input to copy, not a fired classifier).

3. Product Decision Framework

Every nudge leaf is a cell in a MECE decision tree over four axes. The backend supplies A and D at session start; the client evaluates B and C from live counters.

AxisValuesMeaning / source
A — User intent prior Exploit (dominant sscat S) · Explore (wide, no dominant S) · Cold (no history) Backend classification from trailing behaviour (exploit threshold ~50% of clicks in S over N-day lookback). Cold users fall to a safe generic leaf.
B — Current-session click state Zero clicks · Clicked on-intent (in S) · Clicked off-intent / wide Client, from sscat-tagged click counters.
C — Search state (this session) No search · Searched Gates leaves that assume intent is unexpressed (E3, X1). Client session_searched_flag.
D — Prior-session hook None · Prev-clicked product not re-shown · Intent carry-over (cart / payment / wishlist abandonment) Backend-pushed prior-session state; produces override nudges evaluated at app open.

3.1 Nudge Catalogue & Hypotheses

Copy is Hindi-forward with English retail terms, consistent with shipped v1 nudges. Curly-brace tokens are placeholders resolved from the context payload (§II.6). The Priority column drives the resolver (§II.5).

Explore user (no dominant sscat; predicted basket Z)

IDTrigger conditionHypothesisCopy (placeholder)Priority
X1 Explore; zero clicks; ≥ min categories viewed; no search; Z−Y non-empty and Z-confidence ≥ threshold we can predict a category they haven't seen yet that they're likely to want “shayad aap {predicted_categories} dhoondh rahe hain? Bataiye, main seedha wahaan le chalti hoon.” base (explore)
X2 Explore; low Z-confidence OR Z−Y empty we cannot safely assert intent — ask, don't guess “aap aaj kya dhoondh rahe hain? Naam ya kaam bataiye, main madad karti hoon.” base (explore, fallback)

DECISION Z−Y predicted-basket set arithmetic — pre-push + client subtraction.

Z (predicted basket, category-level) is pushed at session start with a confidence score. The client tracks Y (categories actually viewed this session) via the sscat→category rollup map, and computes Z−Y locally to name only unseen predicted categories. Gate: only speak the predicted list (X1) when Z-confidence ≥ threshold (start 0.6). Below it, or when Z−Y is empty, fall to X2's open question — never assert a weak propensity guess as if it were known intent.

3.2 Suppression & Back-off

We want to add configurability and control regarding how many nudges appear in a session, which nudges take priority, and how many nudges a user receives over their lifetime (within the last N days), based on the absolute number of times nudges have been displayed or the number/percentage of times they have been ignored.

Example:

Suppression

  • Vaani already used this session → no nudge.

  • Any product click before eligibility on a zero-click leaf → that leaf is ineligible.

  • Search performed before eligibility → search-gated leaves (E3, X1) do not fire.

Back-off / fatigue

  • Session cap: 1 zero-click nudge per session (carried from v1).

  • Lifetime cap per leaf and global, over a rolling x-day window (config).

  • Ignored-count and ignored-% back-off: after N ignores in the window, suppress globally for the cooldown.

4 Technical Requirements

4.1 Backend ↔ Client Split & Session-Start Payload

The backend computes anything that needs history or cross-session state and pushes a per-user payload at session start; the client evaluates live-session state and fills templates. No fire-time backend call in v2.

Backend-supplied data points (session-start payload)

FieldTypePurpose
intent_prior enum: exploit / explore / cold Axis A — which family of leaves is live.
dominant_sscat (S) sscat_id + display name Fills {sscat} in exploit copy.
is_new_to_category bool Gates E1-NTC.
predicted_basket_Z list[category_id] + confidence Explore X1 predicted list; gated by confidence threshold.
prior_clicked_not_reshown product_id + display name Gates E1-RV; fills {product}.
intent_carryover enum: cart / payment / wishlist + ref D-hook override nudges.
sscat_to_category_map map Client rollup for Y and Z−Y subtraction.
profile_placeholders object (see §6.3) Optional bankable personalization tokens.
z_confidence_threshold float Config; default 0.6.

Client-derived state (live session)

  • session_searched_flag, per-sscat impression/click maps, S-share of views & clicks.

  • Y = distinct categories viewed this session (via rollup map); distinct-sscat count.

  • v1 counters carried forward: session/ surface / surface-visit product views, distinct views, clicks, time.

4.2 Counter Requirements (v2 additions)

v1 session / surface / surface-visit counters are carried forward unchanged. v2 adds sscat-tagged maps and derived counters.

sscat-tagged maps (client)

CounterTypeResetDescription
sscat_product_views map<sscat_id,int> New session Impressions tagged by sscat.
sscat_product_clicks map<sscat_id,int> New session Clicks tagged by sscat.
categories_viewed (Y) set<category_id> New session Rolled up from sscat views via map.
distinct_sscat_count int New session Breadth signal for E4b / explore.

Derived counters

  • s_share_views = views(S) / total_views; s_share_clicks = clicks(S) / total_clicks.

  • predicted_unseen = Z − Y (client set subtraction), used by X1 only when Z-confidence ≥ threshold.

Nudge-state store

  • nudges_shown_by_leaf (rolling window), ignored_count, ignored_pct, last_nudge_ts.
