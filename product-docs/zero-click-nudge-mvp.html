KRD — Vaani Zero-Click Nudge MVP

Current Version: v1
Current Status: Under development
Last Updated: 10 June 2026
POD: Vaani for 1+
Contributors: PM: Ishan | Engineer: TBD | Analyst: Supratik Vishnu

Section I: Executive Summary

1. Problem Statement

Today, Vaani nudges are primarily triggered through existing page-level or repeated-page-visit logic. Current rules already support surfaces such as CATALOG_SEARCH_RESULTS, CATALOG_LISTING_PAGE, SINGLE_PRODUCT, CART, PAYMENT_SELECTION, and MAIN, using triggers like page_intro and repeated_page_visit_without_engagement.

However, we currently do not have a way to identify a user who is viewing multiple products but not clicking on any product. This is a likely zero-click drop-off pattern. The immediate goal is to run a small MVP experiment where Android tracks product impressions and product clicks client-side, and triggers one Vaani nudge per session when the user has viewed enough products without any product click.

This KRD covers only the immediate development needed for the MVP experiment. It does not cover the full future nudge infra, previous-session intent memory, SSCAT overlap logic, backend-generated personalized content, or global advanced nudge orchestration.

2. Scope of Immediate Development

2.1 In Scope

The immediate MVP should support the following:

  1. Client-side product impression counter.

  2. Client-side product click counter.

  3. One zero-click nudge per app session.

  4. Surface support for:

    • Search / CATALOG_SEARCH_RESULTS

    • FY / MAIN

    • CLP / CATALOG_LISTING_PAGE

  5. Counter instrumentation for:

    • FY / MAIN

    • CLP / CATALOG_LISTING_PAGE

    • Search / CATALOG_SEARCH_RESULTS

  6. Remote-config driven threshold and copy.

  7. Basic logs for eligibility, shown, cancelled/suppressed, and outcome.

  8. A/B experiment support with user-level sticky assignment.

2.2 Out of Scope

The following are not required for this immediate development:

  1. Backend rule engine change.

  2. Backend-generated personalized nudge content.

  3. Previous-session no-click logic.

  4. Previous intent / cart / wishlist / payment recovery logic.

  5. SSCAT overlap logic.

  6. Global cross-nudge cooldown across all existing nudges.

  7. Lifetime nudge count.

  8. Ignored nudges count.

  9. ML-based drop-off prediction.

  10. Multi-nudge priority resolver.

5. Surface Visit Definitions

5.1 Search Results

Start/reset current_surface_visit_* when:

User lands on CATALOG_SEARCH_RESULTS

New search query loads

Search result feed is refreshed for a new query

End visit when:

User leaves search result screen

User opens PDP

User moves to another major surface

App backgrounds/session ends

5.2 FY / MAIN

Start/reset current_surface_visit_* when:

User lands on FY / MAIN feed

User returns to FY after visiting another major surface

New app session starts on FY

End visit when:

User leaves FY

User opens PDP

User moves to search/CLP/cart/payment

App backgrounds/session ends

5.3 CLP

CLP counters should be instrumented but not used for nudge firing in this MVP unless config later includes CATALOG_LISTING_PAGE.

Start/reset current_surface_visit_* when:

User lands on CATALOG_LISTING_PAGE

User changes CLP/category context

End visit when:

User leaves CLP

User opens PDP

App backgrounds/session ends

6. Sample Config.

For following type of hypothesis, this type of config will be written

Use Case 1: Session-Level Zero Click

Trigger a nudge when the user has viewed at least 8 products across the entire session but has not clicked on any product.

Logic:

  • session_product_views >= 8

  • session_product_clicks == 0

  • vaani_used_current_session == false

  • zero_click_nudges_shown_current_session < 1

Objective:
Identify users who are browsing across the app but are not finding anything compelling enough to click on, and proactively offer Vaani assistance.

Use Case 2: FY Feed-Level Zero Click

Trigger a nudge when the user has viewed at least 10 products on the FY (For You) feed but has not clicked on any product.

Logic:

  • current_surface = FY / MAIN

  • current_surface_product_views >= 10

  • current_surface_product_clicks == 0

  • session_product_clicks == 0

  • vaani_used_current_session == false

Objective:
Identify users who are consuming feed content but are not engaging with any products, and encourage them to express what they are looking for through Vaani.

Use Case 3: Search Feed Zero Click

Trigger a nudge when the user has viewed at least 5 products within the current Search Results feed visit but has not clicked on any product.

Logic:

  • current_surface = CATALOG_SEARCH_RESULTS

  • current_surface_visit_product_views >= 5

  • current_surface_visit_product_clicks == 0

  • session_product_clicks == 0

  • vaani_used_current_session == false
