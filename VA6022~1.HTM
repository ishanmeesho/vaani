What are people actually asking Vaani for? — query intent classification

Every post_search_query was scanned for 9 refinement signals (color, budget/price, size/fit, material/fabric, texture/feel, gender/age, occasion/use, style/design, brand/model) and checked against whether it's just a bare repeat of the category name — done independently at all three granularities. Compared across three groups at each level: Same dominant (search matches the single most-viewed pre-nudge category), Same any-pre (matches a pre-viewed category, but not the most-viewed one), and Different (matches no pre-viewed category at all). This is a keyword-based heuristic, not exhaustive — e.g. "silky"/"soft" needed adding a texture/feel category and material adjective-forms separately from the base material list, and Hindi/Hinglish phrasing (e.g. "bartan saaf karne ki chuna") isn't parsed at all, so treat "descriptive, no tagged attribute" as "specific but not caught by these 9 lists," not "generic."

Net read: the closer the match (finer grain, higher up the Same-dominant/any-pre/Different ladder), the more likely the query carries a specific, actionable refinement rather than a generic re-ask.

Methodology & caveats

Population: adopted nudges (nudge_zero-click%, adopted = true) with a Vaani search within 60 seconds after the nudge. Nudges with no search, or a later search, are excluded from this dataset entirely.

Pre-signal: the sscat_id of the user's most recent pre-nudge product/catalog impression, using only impressions on that same latest screen (via m.origin).

Post-signal: the sscat_id of the search query that followed, from search_metric_store.

scat / category roll-up: the same pre-nudge sscat_id(s) and post-search sscat_id are mapped up to their parent scat_id / category_id via platinum.product_supplier_catalog_attributes WHERE valid_product_flag = 1 AND dim__dt = DATE '2026-07-28' (4,099 sscat rows). This is a clean 1:1 tree — no sscat rolls up to more than one scat, no scat rolls up to more than one category — and every sscat_id in the 3-day dataset matched with 0 misses. No new pre/post nudge query was run for the roll-up; it's a pure remap of the sscat-level data already pulled from the three original day files (data_25th/26th/27th_july_2026_sscat_Aanalysis).

Portfolio excluded on purpose: the source table's portfolio column doesn't sit cleanly above category — the same category (e.g. "Home & Kitchen") appears under multiple portfolios, so it isn't a strict parent the way category → scat → sscat is.

same_dominant = post-search category matches the single most-viewed pre-nudge category exactly (at whichever level — sscat/scat/category — is being shown). same_any_pre = matches any category viewed pre-nudge (looser). no_signal = no qualifying pre-impression found at all — identical across all three levels since it's about impression existence, not category. Note the scat/category "dominant" match is a roll-up of the sscat-level dominant category, not a re-aggregation of raw view counts at that level — in rare cases where a screen's views split near-evenly across two sscats in the same scat, this could slightly understate the true scat-level dominant match. The any-pre version has no such caveat — it's an exact roll-up.

Caveat: long tail of low-volume screens (n<50) — treat their percentages as noise, not signal. Audience 168648 fires conservative-variant nudges exclusively; 168649 fires aggressive-variant nudges exclusively — audience and variant type are the same split in this data, not independent factors.
